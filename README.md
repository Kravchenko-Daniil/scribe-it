## 🌱 Что это

Нужен текст интервью, подкаста, лекции или совещания — обычно приходится либо расшифровывать руками, либо идти на платные веб-сервисы с аккаунтами. Долго.

**scribe-it делает то же за минуту.** Кидаешь файл или ссылку → получаешь `.txt` с абзацами и разделением по спикерам. Транскрипция — на [ElevenLabs Scribe](https://elevenlabs.io/speech-to-text).

## 🏗 Архитектура

**Центр продукта — API.** Telegram-бот (и будущий сайт) — тонкие HTTP-клиенты: своей логики не имеют, только зовут API.

```
Telegram-бот ┐
             ├─HTTP→  API  ─→  ядро: источник → скачать → ffmpeg→opus → Scribe → текст
Сайт (позже) ┘                 кеш (sha256 opus, TTL 30д)
```

- **`api.py`** — единственное место, где идёт работа: job-модель на диске, эндпоинты, кеш, очистки.
- **`bot.py`** — тонкий клиент: принял файл/ссылку из Telegram → отдал API → вернул юзеру `.txt`.
- **`core/`** — вся логика ядра: `resolve` источника, `download` (yt-dlp/ffmpeg/Яндекс), `scribe` (Scribe + рендер txt/srt), `storage`, `cache`.

## ⚡ Вход

Любой источник сводится к списку медиа-элементов; папку и плейлист сервис перебирает сам.

| Что принимает | Одиночный | Множественный | Лимит |
|---|---|---|---|
| Файл в Telegram | да | — | до 2 ГБ (self-hosted Bot API) или 20 МБ (стандартный) |
| YouTube | видео | плейлист → все ролики | любая длина |
| Яндекс.Диск | файл | папка → все файлы | любой размер |
| Google Drive / прямой http | файл | — | любой размер |

Большие видео проще залить на YouTube как unlisted или на Яндекс.Диск и прислать ссылку — сервис сам скачает.

## 📤 Выход

Один **`.txt`** на каждый элемент источника: чистый текст, разбитый на абзацы и по спикерам. Имя файла = название записи. Элемент папки/плейлиста может упасть индивидуально — остальные всё равно доедут.

## 💬 Подсказки модели в подписи

Подпись к файлу (или вторая строка после ссылки) уточняет спикеров и язык — часто чище, чем автоопределение:

| Подпись | Что значит |
|---|---|
| `2` | диалог двух людей |
| `соло` / `монолог` | один спикер |
| `Даниил Толя` | 2 спикера, имена в порядке появления |
| `2 Даниил Толя` | явно и число, и имена |
| `en` / `англ` | язык, если запись не на русском (иначе Scribe определит сам) |
| пусто | модель решает сама |

Непонятная подпись (`2 спикера`, `созвон с Толей`, любая фраза) → бот считает, что подсказки нет, и идёт в авто-режим.

## 🧠 Кеш

Транскрипция — единственный платный шаг, поэтому кешируется её результат.

- Храним **только сырой ответ Scribe** (`.json`); `.txt`/`.srt` пересобираются на чтении.
- **Ключ** = `sha256(opus)` (выход ffmpeg) + язык + число спикеров + отсортированные `biased_keywords`. Display-имена спикеров — на рендере, в ключ НЕ входят (смена имени кеш не инвалидирует).
- **TTL 30 дней** по mtime, скользящий (хит продлевает), фоновая эвикция.
- Повтор того же аудио пропускает оплачиваемый шаг Scribe. Скачивание и ffmpeg→opus всё равно выполняются — «мгновенно» относится только к Scribe.

## 🔌 API (контракт)

| Метод | Назначение |
|---|---|
| `POST /jobs` | один из `{ url \| local_path \| multipart-файл }` (+ опц. `language`, `num_speakers`, `speaker_names`) → `{ job_id }`, статус `queued` мгновенно |
| `GET /jobs/{id}` | `{ status, items:[{ index, name, stem, text, status, stage, error }], error }` |
| `GET /health` | 200 только если API прочитал `ELEVENLABS_API_KEY` (охраняет деплой-катовер) |

`local_path` — основной путь бота: файл из Telegram стейджится под общий `SCRIBE_STAGING_DIR` на одной ФС с download-каталогом Bot-API и передаётся без перезаливки.

## 📦 Запуск

```bash
uv sync
uv run uvicorn api:app --host 127.0.0.1 --port 8080   # API — сначала
uv run python bot.py                                   # бот — тонкий клиент
```

Пути и адреса задаются через env с дефолтами (`SCRIBE_TMP_DIR`, `SCRIBE_CACHE_DIR`, `SCRIBE_STAGING_DIR`, `SCRIBE_JOBS_DIR`, `SCRIBE_API_URL`, `BOTAPI_DOWNLOAD_DIR`) — дефолты указывают в прод-пути под `/opt/scribe-bot`. Секреты (`ELEVENLABS_API_KEY` у API, `TELEGRAM_BOT_TOKEN`/`OWNER_ID` у бота) — в `.env.<APP_ENV>`. В проде — два systemd-юнита (`scribe-api.service` → `scribe-bot.service`), деплой через `deploy/deploy.sh` (rsync → uv sync → health-gate).
